01 项目速览 这个目录里到底是什么

PROMESST 2 是一款俯视 2D 光束解谜游戏:玩家控制角色走在一个环形卷绕的瓦片世界上,借助 8 种颜色的光束(投影器)、宝石、反射镜、魔杖与自动游走的机器人(rover)完成谜题。站在某种颜色的光束里,角色就能获得对应的“能力”,例如开门、穿墙、粉碎石块、二倍步进或沿光束远行。

代码无任何外部库依赖:图像解码、OpenGL 封装、窗口创建全部通过随附的 stb 单文件库内联编译(stb_image.c 以 #include 方式嵌进 main.c)。这是典型的 stb 作者“自用即开源”风格作品:全手绘像素美术、ASCII 关卡、注释里保留了大量设计草稿。

游戏类型
回合式移动 + 实时机器人的光照解谜(Chip's Challenge 风格)
世界规模
上下两层(z = 0/1),每层 4×4 = 16 个 6×6 房间,共 32 个房间;世界环形卷绕,楼梯 # 切换层
核心循环
移动 / 拾取宝石 / 开门穿墙 → 点亮房间(宝石填满底座给投影器供电)→ 产生光束能力 → 破解障碍 → 把 30 颗宝石喂给蜥蜴机器人通关
操作
方向键 / WASD 移动,Z 发射(魔杖),X 拾取/放置宝石,C 反射镜(代码中仍绑定),退格 撤销到进入本房间之前,Esc 菜单
开发特征
大量 #if 0 备选玩法、被禁用的功能、设计注释——源码即开发日记

06 机制详解 把每个子系统讲清楚

6.1 世界 / 房间模型

世界是 24×24×2 的环形(卷绕)网格:坐标越界用 WRAP_X/WRAP_Y(L723–724)取模,没有世界边缘。网格被切成 4×4 的“房间”,每房间 6×6(NUM_X/Y=4, SIZE_X/Y=6,L200–203)。游戏逻辑几乎只关心玩家所在房间及其 8 邻居:

  • compute_room()(L466):由玩家坐标算出当前房间号。
  • 每帧 draw_world 只渲染 8×8 窗口(当前房间外扩一圈,L1893 起循环 -1..SIZE_X),超出部分卷绕回世界另一侧——所以画面总是“无缝”的。
  • 移动到房间边界的门/墙就是“关卡之间的通道”;# 楼梯在 z 维切换。

6.2 光照与能力系统(核心玩法)

整个谜题体系围绕“通电的投影器发射彩色光束;角色被光照到就能使用对应能力”构建:

  1. 供电 compute_powered()(L475):某房间只要存在底座且底座全部被宝石占据,has_power[ry][rx]=1 —— 宝石谜题驱动光束的开关。
  2. 传播 propagate_light()(L496):对每个有电投影器沿其方向逐格行进;穿过反射镜可 90° 折转或折返(dir ^= 1 / dir ^= 3,L516–521);遇门、石块、rover 等非空物即停(L513/522–525);世界四周卷绕(L511–512)。结果写入 light_for_dir[y][x][方向]=颜色。
  3. 能力判定 get_abilities()(L714):站在玩家格上,统计从 4 个方向照入的光颜色,enabled[颜色]++。
  4. 能力生效 在 move() 内:红→门可打开并消耗;绿→墙视为可通行;黄→面前石块被粉碎;橙→本次步数 ×2^照入数(双步);紫→沿光束方向滑到光束尽头(travel,L757–770)。使用过的能力写入 ability_flag 供 HUD 显示。
  5. Z 键(魔杖) shoot()(L1026):收集所有正照在玩家身上的投影器(find_lights_on_player,L538),把它们的照射方向重定向为玩家当前朝向——“站在光里把它引向别处”是全局最核心的谜题操作,成功一次 num_zaps++(通关统计“USED n ZAPS”)。

渲染侧把光束画成彩色发光格:普通层先画、然后 glBlendFunc(GL_SRC_ALPHA, GL_ONE) 加法混合叠加光束辉光(L2075 起),观感上光束会“染”亮地板与物体。

6.3 移动与玩家操作

按键(逻辑键)函数行为
方向键 / WASDmove() L742逐格移动(速度 80ms/步)。按规则依次判定:紫光远行 → 橙光双步 → 站墙(绿) → 面前是投影器则不许站 → 撞墙(需绿) → 门(需红,开门不前进) → 石块(需黄,原地砸碎) → 魔杖(拾取并建 checkpoint) → 楼梯切层。移动动画插值见渲染 L2004。
Xdrop() L855站在宝石上 = 捡起(num_gems++);身上有宝石且脚下是底座 = 放下(方向置 1,宝石开始变色动画)。放下后重算供电/光照。
Zshoot() L1026需魔杖;重定向照到自己的投影器(见 6.2)。
Creflector() L876需反射镜:拾取 / 放下 / 切换斜向。HUD 提示被 #if 0 掉但按键仍生效。
退格restore_undo() L641撤销到进入当前房间之前(见 6.4)。
Esc—返回菜单(可 CONTINUE / 从 checkpoint 恢复 / 新游戏 / Credits / 存盘退出)。
g / n—仅 _DEBUG 或 CHEAT 编译时:作弊给 30 宝石+魔杖 / 开关穿墙。

6.4 撤销系统(带说明的经典实现)

需求是 readme 里的“撤销到进入当前房间之前”。实现巧妙在不存全图:进入新房间那一刻,把“上一房间可能被本房间改动过的全部格子”压缩保存 —— 因为玩家离开一个房间后,能影响该房间的只有“从本房间延伸出去的横向/纵向整条带子上的物体”以及被打开的门,于是 roomsave_big 只存:

  • 玩家进入时点之前的 player_state;
  • 该房间 横向 6×24 与 纵向 24×6 两条十字的物体带(h_objmap / v_objmap);
  • 该房间每行的门位图 doors[SIZE_Y]。

节点压入 undo_chain 链表(L613–639)。退格 = 弹出最近节点并把十字带与门状态写回、恢复玩家位置(restore_undo,L641–673)。L404–461 的长注释解释了设计取舍,还包含一个被放弃的“小 roomsave”方案(#if 0)。注意:此撤销随进入房间自动打点,与玩家动作数量无关,所以任何一步出错退格即可“回到进门前”。

6.5 Rover(自动机器人)AI

& 标记的 rover 每 ROVER_MOVE_TIME(630ms)在各自房间内同步移动一格(move_rovers,L1140)。逻辑要点:

  • 同步移动:先让每个 rover 声明“想去哪”,用 occupied 冲突表,迭代到不动点,避免互相穿模(L1146–1215)。
  • 转向:rover 踩到箭头瓦片就朝箭头方向走;走不了则掉头(preferred_rove_direction,L1118)。
  • 吃宝石:rover 前方是宝石就吃掉:gems_stored++,同时 feed_timer=1200(蜥蜴开口说话)、reverse_timer=1100(吃完反向游走一阵,L1200–1204)。
  • rover 可穿过玩家(L1103 的禁止被 #if 0);push_rovers()(L726)是永远 return 0 的空壳,玩家推 rover 的功能同样被裁。

6.6 主循环与事件流

平台层由 stb_wingraph(或 SDL 版)驱动,stbwingraph_MainLoop(loopmode, 0.016f)(L2542)每 ~16ms 回调一次 loopmode()(L2432),框架:

winproc (L2463) ── 事件
  └ 字符/方向键 → queued_key('w/a/s/d' 等)
loopmode (L2432) ── 每帧
  ├ M_game:  dt 夹到 [0.01, 0.25] → timestep(ms) 递减各计时器、按节拍消费 queued_key、驱动 rover、积累 egg_timer
  ├ 其它模式: process_metagame(Logo 倒计时 → 菜单)
  └ 窗口激活时 → draw() = draw_init + draw_world + SwapBuffers

queued_key 的“排队”保证移动动画(80ms)进行中的按键不丢不重;timestep 里只有 player_timer <= 0 且 shot_timer <= 0 才执行 do_key(L1317–1320)。窗口失活自动暂停更新(返回 STBWINGRAPH_update_pause)。

6.7 胜利条件(喂蜥蜴)

目标是把 MAX_GEMS = 30 颗宝石喂给世界里的 rover。当 gems_stored ≥ 30(L1322):egg_timer 开始累积并驱动一串过场动画(draw_world L2035–2069, L2382–2417):

  1. egg_timer > 0:被喂的 rover 停止移动,原地变成一只彩虹色蜥蜴(HSV 色轮上色),同房间(2,3,0 层)里不断冒出气泡文字:%d MORE / NEED MORE / WELL NOW(L2144–2191)——你一直喂的那只其实就是结局 NPC。
  2. >8000ms:全屏紫色闪光渐强;
  3. >14000ms:黑底大号 YOU WIN;
  4. >17000ms:显示 USED n ZAPS(整局按 Z 的次数);
  5. >22000ms:exit(0) —— 注释直言“不应存档!”(通关不留档)。

6.8 存档格式(顺序二进制)

save_game()(L1488)把三块按序写进文件,load_game()(L1459)顺序读回:

1. gamestate(全图 tilemap+objmap+player_state)  // 当前局面
2. checkpoint(同上结构)  // 拾取魔杖时快照
3. roomsave_big × N  // 撤销链逐节点(指针 next 置 0 后落盘)
  • 路径:Windows 为 data2/save.dat(L1413);Linux 为 $XDG_DATA_HOME/Promesst2/save.dat 或 ~/.local/share/…,并逐级 mkdir(L1416–1456)。
  • 触发:窗口销毁自动保存(L2485)+ 菜单 “SAVE AND QUIT”(L1543)。RELEASE 未定义时 save_game 直接 return(不写盘,L1494–1496)。
  • 启动流程(stbwingraph_main L2531–2539):RELEASE 下先 restart_game() 再 load_game(),有档则默认菜单停到 “CONTINUE GAME”;否则直接进游戏。
