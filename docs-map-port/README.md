## 1. 定位与总原则

### 1.1 一句话

把《PROMESST 2》的**玩法规则**逐函数移植为「原生 JS + Canvas 单页应用」;画面沿用原精灵表,**游戏视野改为完整大地图**,界面层(HUD/菜单/存档)由 HTML 承载。

### 1.2 三条红线

1. **玩法逻辑保真**:移动判定、能力语义、供电、光束、Rover、逐步撤销、存档与原版一致(除 §0 三项裁定外);
2. **渲染尽量还原**:精灵/调色/光束/动画插值沿用原公式;允许观感近似(§8);
3. **网页层自由**:HUD、菜单、提示可重做,不影响规则。

### 1.3 视野裁定说明(为何可行)

原版的“单房间取景”只是**绘制层的裁剪**:逻辑一直在整幅 24×24 卷绕世界上运行,房间仅是 6×6 逻辑分区(供电/调色/最小化提示用)。因此把视口从“当前房间+外圈”改为“整幅地图”**不改变任何规则**,只改渲染取景与随之而来的撤销锚点(裁定 2)。

## 2. 范围与保真边界

### 2.1 必做(规则相关)

- 完整世界:两层 24×24(4×4 房间 × 6×6),环形卷绕(边缘无缝,原规则);
- **整图视野**:任意时刻可见完整当前层;缩放(1–4×)与“跟随玩家”(放大时)为可选项;
- 玩家移动 + 5 色能力:红开门 / 绿穿墙 / 黄碎石 / 橙双步 / 紫沿光束远行;
- X 拾/放宝石 → 房间供电 → 光束点亮;Z(魔杖)重定向照到玩家的投影器;
- Rover 同步移动 / 踩箭头转向 / 吃宝石与反转计时(全地图各房间照常自主运行);
- **逐步撤销**(栈,见 §6.6)、checkpoint(拾魔杖生成、菜单可恢复);
- 存/读档(含撤销栈)、通关动画与 USED n ZAPS;
- 菜单:继续 / 从 wand 恢复 / 新游戏 / Credits / 存盘退出。

### 2.2 不做 / 可裁

- `magic_phase` 房间旋转(L1253–1299):原版即不可达 → 不移植;
- 4 个 `#if 0` 的 `shoot()` 与 `push_rovers` 空壳:不移植;
- 触屏/手柄(B 裁定 3);声音(原版无音频,不新增);
- 反射镜 C 键玩法:关卡中 `/` 出现 0 次、无来源 → **逻辑照抄、HUD 隐藏**(§7 F 行)。

## 3. 总体架构

```
┌────────────────────────────────────────────────────┐
│ Platform(网页专属)                                  │
│  · rAF 主循环 → 固定 16ms 逻辑步进 + 渲染          │
│  · 键盘(方向/WASD/Z/X/C/退格/Esc) → 排队按键队列   │
│  · localStorage 存档 / 槽位 / 导出导入              │
├────────────────────────────────────────────────────┤
│ Core(规则内核,零 DOM,可单测)                      │
│  world: tilemap/objmap/player_state + 解析          │
│  sim:   update(ms) = timestep(L1237) 移植          │
│  ├─ actions  move/drop/reflector/shoot              │
│  ├─ light    powered + propagate(L475–577)          │
│  ├─ rover    stepRovers(纯函数,L1093–1218)         │
│  └─ memory   逐步撤销栈 + checkpoint + 存档         │
├────────────────────────────────────────────────────┤
│ Render(Canvas 世界层)                              │
│  · 整幅当前层渲染(调色/精灵/光束/插值/缩放)        │
│  · 世界内文字用精灵表内置字体绘制                   │
├────────────────────────────────────────────────────┤
│ UI(HTML/DOM 层)                                    │
│  · HUD:能力灯/宝石计数/按键提示/撤销按钮            │
│  · 菜单/Logo/Credits/存档管理页面                    │
└────────────────────────────────────────────────────┘
```

内核只读状态、只被 `update(ms)` 变更;渲染与 UI 只读快照。

## 6. 关键技术决策

### 6.1 主循环:rAF + 固定 16ms 步进

- 累积 dt,每 16ms 一次 `update(16)`;dt 超 250ms 复位(等价 L2444 clamp);
- `update(ms)` = `timestep` 移植:**递减计时器 → rover 自主步进 → 消费排队按键**;
- 插值照抄:玩家 80ms 滑动(L2004–2009)、rover 630ms 尾段滑步(L1978–1984);
- 按键**排队**:事件写 `queuedKey`,仅当 `player_timer<=0 && shot_timer<=0` 执行(L1317–1320)→ 复刻按住方向每 80ms 走一步、不吞键。

### 6.2 输入(裁定 3:仅桌面键盘)

| 原版 | Web |
|---|---|
| 方向键 | 方向键 + WASD |
| Z / X / C | 同键;C 逻辑保留但无 HUD 提示(照抄) |
| Backspace 撤销(1 ROOM) | Backspace **撤销上一步**(文本/行为按裁定 2) |
| Esc | Esc + HUD 菜单按钮 |
| 调试 g/n | 隐藏调试面板开关 |

### 6.3 渲染与整图取景(裁定 1)

- 一帧 = **整幅 24×24 当前层(`pz`)全部绘出**,默认等比适配窗口(黑边);缩放 1–4× 可选,放大后可用“跟随玩家中心”或自由平移;
- 两层切换:`pz` 变化(走楼梯)时自动切到对应层;额外提供“查看另一层”按键仅切换视角不改 `pz`(装饰功能,不影响规则);
- 调色/光束/精灵管线复用 map/ 已验证方案(multiply 调色、lighter 加法辉光、房间底色取样);
- 世界内飘字(蜥蜴气泡/YOU WIN 等)用内置字体绘制;HUD 归 DOM;
- 窗口等比缩放对应原 `draw_init`(L1587–1608)。

> 说明:原版画 8×8 窗口(当前房间+外圈)纯属取景裁剪(L1893 循环范围),改成整幅后其余绘制逻辑(L1851–2418 的主体)不变。

### 6.4 动作模型(玩家操作时序)

每次**可能改变世界**的玩家操作按序:

1. `pushUndo()` —— 若将产生状态变化(判定依据见下),先把**整幅世界 + 玩家 + rover/feed/reverse 等计时器**压入撤销栈(§6.6);
2. 执行动作(移动/开门/碎石/拾魔杖/拾放宝石/射光改向);
3. 结算:重算供电/光照(仅当前层需要?——**全层重算**,见 §6.5 注)。

动作判定顺序照抄 `move()` L742–853(远行→双步→noclip→站墙→投影器→墙→门→石块→魔杖→切层),仅去掉“跨房间撤销打点”与 `seen` 更新。

### 6.5 Rover(最容易错,纯函数化)

- 每房间独立、每 630ms 同步一轮(L1140–1218);
- 先全部声明目标 → `occupied` 冲突表 → 迭代到不动点 → 落子;
- 踩箭头沿箭头;被堵/冲突掉头;目标为宝石则吃并计 `gems_stored` + feed/reverse 计时;第 0 个 rover 反转特殊规则照抄(L1168–1171);
- **自主运行**:玩家静止时 rover 照常步进(与 L1300–1309 一致);
- 供电/光照需跨房间重算(rover 吃到宝石会改变供电房状态)——因此 `update` 中 rover 步进后重算当前层光照;若影响另一层供电,切层时重算即可(不透明优化见 §6.5 注 2)。

> 注 1:原版只重算“当前房间”的光照(L496 基于 room_z 的全局缓存按房间逐次覆盖),视野与撤销改动不改变此语义;**建议保持“rover 步进后重算当前层光照”**,避免视觉与能力判定漂移。
> 注 2:另一层仅在玩家切层时重新计算,与“查看另一层”装饰视图解耦。

### 6.6 逐步撤销(裁定 2)

- **触发点**:在动作执行前,若该动作会改变世界(可预判:移动成功/开门/碎石/拾魔杖/拾放宝石/射光改变了投影器朝向),则先压栈;撞墙未生效等 no-op 不压栈;
- **快照内容**:整幅 `gamestate`(两层 tilemap+objmap)+ `player_state` + rover/feed/reverse/egg_timer 等计时器现值 —— 因为 rover 是自主移动的,只有“完整时刻快照”才能让退格精确回到上一步(含 rover 位置与已吃宝石);
- **容量**:每份约 ≤5 KB,上限 256 步(超出丢最旧),内存与持久化均可控;
- **恢复**:退格 = 弹栈 → `restoreMap` 等价物 + 计时器复位 → 重算光照;新游戏/从 checkpoint 恢复时清空栈;
- 与 checkpoint(拾魔杖快照、菜单“从 wand 恢复”)并存,互不干扰;
- HUD 文本:原版“UNDO 1 ROOM”改为“撤销上一步(Backspace)”;

> 语义说明:玩家原地等待期间 rover 自主移动(可能吃宝石)也算入“上一步之后的世界”;退格会把这些一并回退,与原版“回房间”回退本房间 rover 的语义在整图下等价且更直觉。

### 6.7 存档 Schema(Web)

- `localStorage`,键 `promesst2.save.v1`,JSON;
- 结构:`{meta, gamestate, checkpoint, undoStack[]}`(undoStack 为快照栈,替代 roomsave_big 链);
- meta:槽名/版本/通关标记/num_zaps/时间戳;多槽 3 个(内核只认活动槽);
- 加载失败 → 视作无档并提示,不覆盖。

### 6.8 结局与元流程

- `egg_timer` 驱动 8000/14000/17000/22000 四阶段(紫白闪→YOU WIN→USED n ZAPS→结算页);
- Web 结算页回到标题/再玩一次,通关标记写 meta(微调,不改规则);
- Logo/Credits 素材沿用 sss_logo/title.png,数据照 L1340–1566。
