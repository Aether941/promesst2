# PROMESST 2 — HTML5 网页版移植设计文档(v3)

> 目标:**玩法逻辑 1:1 保真 + 网页化 UI**,并按下述裁定调整:
> **① 整幅大地图视野(非原版单房间取景)**
> **② 撤销 = 回到上一步(非原版“回到进房前”)**
> **③ 仅桌面键盘;其余照抄原版**
> **④ 撤销尽量无上限(差分存储,至少覆盖整局至通关)**
> **⑤ 支持重做(撤销过头可前进恢复)**
>
> 数据基准:`promesst2_source_code/main.c`(2014-05-18 版,2543 行);文中 `Lnnn` 均指向该文件。
> 可复用件:`map/index.html`、`map/map-data.js`(解析+静态渲染已验证)。

## 1. 定位与总原则

### 1.1 一句话

把《PROMESST 2》的**玩法规则**逐函数移植为「原生 JS + Canvas 单页」;画面沿用原精灵表,**视野为完整大地图**,撤销/重做为**无上限差分历史**;界面层(HUD/菜单/存档)由 HTML 承载。

### 1.2 三条红线

1. **玩法逻辑保真**(除 §0 五项裁定外一律照抄);
2. **渲染尽量还原**(允许观感近似);
3. **网页层自由**(HUD/菜单/提示可重做)。

## 2. 范围与保真边界

### 2.1 必做

- 完整世界:两层 24×24(4×4 房间 × 6×6),环形卷绕;
- **整图视野**:当前层全幅可见,缩放 1–4×(可跟随玩家);“查看另一层”为纯视角装饰;
- 玩家移动 + 5 色能力(红开门/绿穿墙/黄碎石/橙双步/紫远行);
- X 拾/放宝石 → 房间供电 → 光束点亮;Z 重定向投影器;
- Rover 自主同步移动/踩箭头转向/吃宝石与反转(全图 1 只,照原规则运行);
- **逐步撤销 + 重做(无上限,见 §6.6)**、checkpoint(拾魔杖生成、菜单恢复);
- 存/读档(含历史策略,§6.7)、通关动画与 USED n ZAPS;
- 菜单:继续 / 从 wand 恢复 / 新游戏 / Credits / 存盘退出。

### 2.2 不做 / 可裁

- `magic_phase` 房间旋转(L1253–1299):原版不可达 → 不移植;
- 4 个 `#if 0` 的 `shoot()` 与 `push_rovers` 空壳:不移植;
- 触屏/手柄(裁定 3);声音(原版无);
- C 键反射镜:关卡 `/` 0 个、无来源 → 逻辑照抄、HUD 隐藏(§7 F 行)。

## 3. 总体架构

```
┌────────────────────────────────────────────────────┐
│ Platform(网页专属)                                  │
│  · rAF → 固定 16ms 逻辑步进 + 渲染                  │
│  · 键盘(方向/WASD/Z/X/C/退格/重做/Esc)→ 排队按键   │
│  · localStorage(状态+近期历史)/ 可选 IndexedDB      │
├────────────────────────────────────────────────────┤
│ Core(零 DOM,可单测)                                │
│  world: tilemap/objmap/player_state + 解析          │
│  sim:   update(ms) = timestep(L1237) 移植          │
│  ├─ actions  move/drop/reflector/shoot              │
│  ├─ light    powered + propagate(L475–577)          │
│  ├─ rover    stepRovers(纯函数,L1093–1218)         │
│  └─ history  差分撤销栈 + 重做(§6.6)               │
├────────────────────────────────────────────────────┤
│ Render(Canvas 世界层):整幅当前层,调色/光束/插值    │
├────────────────────────────────────────────────────┤
│ UI(HTML/DOM):HUD/菜单/存档/撤销与重做按钮          │
└────────────────────────────────────────────────────┘
```

内核只被 `update(ms)` 变更;所有世界写入经统一访问,供 history 差分。

## 6. 关键技术决策

### 6.1 主循环:rAF + 固定 16ms 步进

同 v2(累积 dt → 每 16ms `update(16)`;超 250ms 复位;按键排队;插值公式照抄)。

### 6.2 输入(裁定 3:仅桌面键盘)

| 原版 | Web |
|---|---|
| 方向键 | 方向键 + WASD |
| Z / X / C | 同键;C 逻辑保留、无 HUD 提示 |
| Backspace 撤销(1 ROOM) | Backspace / Ctrl+Z = **撤销上一步** |
| —(新增) | **Ctrl+Y / Ctrl+Shift+Z / Y = 重做** |
| Esc | Esc + HUD 菜单按钮 |
| 调试 g/n | 隐藏调试面板开关 |

撤销/重做另有 HUD 按钮与“可撤销 N 步 / 可重做 M 步”指示(纯 UI,不影响内核)。

### 6.3 渲染与整图取景(裁定 1)

- 每帧绘整幅 24×24 当前层(`pz`),默认等比适配窗口,缩放 1–4×,放大可跟随玩家/自由平移;
- 走楼梯自动切层;“查看另一层”只切视角不改 `pz`;
- 调色/光束/精灵管线复用 map/ 方案(multiply、lighter、房间底色取样);
- 世界内文字用内置字体;HUD 归 DOM;窗口等比黑边。

### 6.4 动作模型

1. 若操作将改变世界:先按当前状态与最近提交点的**差分**生成 history 条目(§6.6),再执行动作;
2. 执行动作(判定顺序照抄 `move()` L742–853,去掉跨房打点/`seen`);
3. 结算:重算供电/光照;若 rover 自主步进发生,一并落在下一次提交的差分里。

### 6.5 Rover

同 v2:每房间独立 630ms 同步移动、冲突表迭代、箭头转向、吃宝石计 feed/reverse、第 0 个反转特例照抄;玩家静止也照常运行;步进后重算当前层光照。
全图 rover 现状:**1 只**,自主差分极小;实现按通用多 rover 处理。

### 6.6 撤销 / 重做(裁定 2/4/5 —— 差分历史)

**空间分析**

| 方案 | 每步成本 | 2 万步整局 |
|---|---|---|
| 整幅快照 | ~4.6 KB(2×576×4B)+ 状态 | ~90 MB ❌ |
| **差分条目(采用)** | 典型 <200 B(只记变动格 old/new) | **几 MB ✅** |

- 典型一步改动 1–5 格;全图仅 1 只 rover,自主步进也仅 1–2 格 + 偶发吃宝石;
- 每操作提交一次全图 1152 格 diff(廉价),换取不依赖“写入日志”,rover/任何变更都天然入历史。

**模型**

- 状态序列: `S0 →(条目0)→ S1 →(条目1)→ S2 … Sn`;
- 条目 `Ei` 存:差异格列表(坐标编码 k+idx,`old` 与 `new`)、`pre/post` 玩家状态与计时器(feed/reverse/egg_timer/ability_flag/gems_stored/num_zaps/num_gems 等);
- 指针 `p` ∈ [0, n] 表示当前停在 `Sp`。
- **撤销**(`undo()`):`p>0` → 对条目 `E(p-1)` 反向应用(old 侧)+ 恢复其 `pre` 状态;`p--`;重算光照。
- **重做**(`redo()`):`p<n` → 正向应用 `E(p)`(new 侧)+ `post` 状态;`p++`;重算光照。
- **提交**(玩家有效操作后 diff 非空):先丢弃 `E(p..n)` 尾部(重做分支失效),再追加新条目,p=n。
- 无上限(默认);软警戒:内存超阈值(默认 64 MB,可配)时提示并可选压缩(把最旧若干条目两两合并为整幅快照后裁掉一半,或仅提示)。
- checkpoint(拾魔杖)恢复、读档、新游戏 → 清空历史(与原版 `flush_undo` 语义一致)。
- no-op 动作(撞墙未生效等)不产生条目。

> 语义:玩家原地等待时 rover 自主演化也计入世界;条目边界=玩家操作提交点,pre/post 各含当时的 rover/计时器,故撤销/重做均为**精确状态回放**,不做重演,行为与直觉一致。

**按键与边界**

- Backspace / Ctrl+Z 撤销;CtRL+Y / Ctrl+Shift+Z / Y 重做;
- 撤销后执行新操作 → 重做清空(标准);
- 通关结算/新游戏时清历史。

### 6.7 存档 Schema(Web)

- 主存 `localStorage`,键 `promesst2.save.v1`,JSON;
- 结构:`{meta, gamestate, checkpoint, historyPolicy, undoPrefix[]}`;
  - `gamestate/checkpoint`:当前状态与魔杖快照;
  - `undoPrefix[]`:**当前指针 p 之前的已应用条目**(差分),可支撑跨会话继续撤销;
  - `historyPolicy`:`'last300'`(默认)可调;
- 说明:完整“从开局的撤销栈”不写 localStorage(整局历史可达数 MB~数十 MB,超出配额),跨会话默认只保留最近 ~300 步 + 当前完整状态;**局内(不刷新)撤销仍是无上限的**;
- 若需“刷新后仍能从第一步撤销”:改用 IndexedDB 持久化整条历史(设计预留,默认关闭);
- 加载失败 → 视作无档并提示,不覆盖;通关标记写 meta;结算后清历史。

### 6.8 结局与元流程

同 v2:`egg_timer` 四阶段;Web 结算页回标题/再玩一次;Credits 保留原署名。

## 9. 测试与验收

### 9.1 内核单测(新增撤销/重做用例)

- 解析双层格子(回归);
- 供电真值表;光束直射/门/石块/反射镜/卷绕;
