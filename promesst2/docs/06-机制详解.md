# 6. 机制详解

## 6.1 世界 / 房间模型

世界是 **24×24×2 的环形(卷绕)网格**:越界用 `WRAP_X/WRAP_Y`(L723–724)取模,没有边缘。网格切成 **4×4 个“房间”,每房间 6×6**(L200–203)。游戏逻辑几乎只关心玩家所在房间及其 8 邻居:

- `compute_room()`(L466):由玩家坐标算出当前房间号;
- 每帧 `draw_world` 只渲染 8×8 窗口(当前房间外扩一圈,L1893 起循环 `-1..SIZE_X`),超出部分卷绕回世界另一侧,画面“无缝”;
- 房间边界的墙/门就是关卡通道;`#` 楼梯在 `z` 维切换。

## 6.2 光照与能力系统(核心玩法)

1. **供电** `compute_powered()`(L475):房间存在底座且全部被宝石占满 → `has_power[ry][rx] = 1`。宝石谜题驱动光束开关。
2. **传播** `propagate_light()`(L496):每个有电投影器沿方向逐格行进;反射镜 90° 折转或折返(`dir ^= 1` / `dir ^= 3`,L516–521);遇门、石块、rover 等非空物停止(L513/522–525);世界卷绕(L511–512)。结果写入 `light_for_dir[y][x][方向] = 颜色`。
3. **能力判定** `get_abilities()`(L714):统计玩家格四向入射光的颜色,`enabled[颜色]++`。
4. **能力生效** 在 `move()` 内:红→门可开;绿→墙可通行;黄→面前石块粉碎;橙→本次步数 ×2^照入数(双步);紫→沿光束滑到尽头(`travel`,L757–770)。用过即写 `ability_flag` 供 HUD 显示。
5. **Z 键(魔杖)** `shoot()`(L1026):收集所有照在玩家身上的投影器(`find_lights_on_player`,L538),把它们的照射方向**重定向为玩家当前朝向** —— “站在光里把它引向别处”是全局最核心的谜题操作,成功一次 `num_zaps++`(通关统计“USED n ZAPS”)。

> 渲染侧光束是加法混合的发光格:先画普通层,再 `glBlendFunc(GL_SRC_ALPHA, GL_ONE)` 叠光束辉光(L2075 起),光束会“染”亮地板与物体。

## 6.4 撤销系统(经典实现)

需求:“撤销到进入当前房间之前”。实现要点是**不存全图**:进入新房间那一刻,保存“上一房间可能被本房间改动过的全部格子”——玩家离开后能影响该房间的只有从本房间延伸出去的**横/纵十字带上的物体**与**被打开的门**,故 `roomsave_big` 只存:

- 玩家进入前时刻的 `player_state`;
- 该房间横向 6×24 与纵向 24×6 两条物体带(`h_objmap / v_objmap`);
- 该房间每行的门位图 `doors[SIZE_Y]`。

节点压入 `undo_chain` 链表(L613–639)。**退格** = 弹出并把十字带与门状态写回、恢复玩家位置(`restore_undo`,L641–673)。L404–461 的长注释说明设计取舍,含被放弃的“小 roomsave”方案(`#if 0`)。

## 6.5 Rover(自动机器人)AI

`&` 标记的 rover 每 `ROVER_MOVE_TIME`(630ms)在各自房间内**同步移动一格**(`move_rovers`,L1140):

- **同步移动**:先让每个 rover 声明“想去哪”,用 `occupied` 冲突表迭代到不动点,避免互相穿模(L1146–1215);
- **转向**:踩箭头瓦片就沿箭头;被堵或冲突则掉头(`preferred_rove_direction`,L1118);
- **吃宝石**:前方是宝石就吃掉:`gems_stored++`,`feed_timer=1200`(蜥蜴说话)、`reverse_timer=1100`(吃完反向游走,L1200–1204);
- rover 可穿过玩家(L1103 的禁止被 `#if 0`);`push_rovers()`(L726)是永远 return 0 的空壳,推 rover 玩法未完成。

## 6.6 主循环与事件流

平台层由 stb_wingraph(或 SDL 版)驱动,`stbwingraph_MainLoop(loopmode, 0.016f)`(L2542)每 ~16ms 回调一次 `loopmode()`(L2432):

```
winproc (L2463) ── 事件
  └ 字符/方向键 → queued_key('w/a/s/d' 等)
loopmode (L2432) ── 每帧
  ├ M_game:   dt 夹到 [0.01, 0.25] → timestep(ms) 递减各计时器、按节拍消费 queued_key、驱动 rover、攒 egg_timer
  ├ 其它模式:  process_metagame(Logo 倒计时 → 菜单)
  └ 窗口激活时 → draw() = draw_init + draw_world + SwapBuffers
```

`queued_key` 的排队保证移动动画(80ms)期间按键不丢不重:`timestep` 里只有 `player_timer <= 0` 且 `shot_timer <= 0` 才执行 `do_key`(L1317–1320)。窗口失活自动暂停更新。

## 6.7 胜利条件(喂蜥蜴)

目标:把 `MAX_GEMS = 30` 颗宝石喂给世界里的 rover。`gems_stored >= 30`(L1322)后 `egg_timer` 开始累积并驱动过场(`draw_world` L2035–2069 / L2382–2417):

1. `egg_timer > 0`:被喂的 rover 停止移动,变成**彩虹色蜥蜴**(HSV 色轮上色),同房间(2,3,0 层)冒气泡文字 `%d MORE / NEED MORE / WELL NOW`(L2144–2191)——你喂的那只就是结局 NPC;
2. `> 8000ms`:全屏紫→白闪光渐强;
3. `> 14000ms`:黑底大号 **YOU WIN**;
4. `> 17000ms`:显示 **USED n ZAPS**(整局按 Z 次数);
5. `> 22000ms`:`exit(0)` —— 注释直言“不应存档!”(通关不留档)。

## 6.8 存档格式(顺序二进制)

`save_game()`(L1488)把三块按序写进文件,`load_game()`(L1459)顺序读回:

```
1. gamestate(全图 tilemap+objmap+player_state)   // 当前局面
2. checkpoint(同上结构)                            // 拾魔杖时快照
3. roomsave_big × N                                // 撤销链逐节点
```

- 路径:Windows = `data2/save.dat`(L1413);Linux = `$XDG_DATA_HOME/Promesst2/save.dat` 或 `~/.local/share/…`,并逐级 `mkdir`(L1416–1456);
- 触发:窗口销毁自动保存(L2485)+ 菜单 “SAVE AND QUIT”(L1543);非 `RELEASE` 时不写盘(L1494–1496);
- 启动流程(`stbwingraph_main` L2531–2539):RELEASE 下先 `restart_game()` 再 `load_game()`,有档则菜单停在 “CONTINUE GAME”;否则直接开局。
