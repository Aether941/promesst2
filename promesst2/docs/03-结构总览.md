# 3. main.c 结构总览

main.c 大体按“数据 → 逻辑 → 渲染 → 平台”书写:先声明全部全局量与静态表,再自底向上实现函数。按下面 14 个连续分区顺序阅读即可:

| 行号 | 分区 | 内容 |
|---|---|---|
| L1–78 | 头部配置 / 全局 | 宏(`RELEASE`/`CHEAT`/`MAX_GEMS 30`/1024×768)、头文件、`color` 结构、8 色 powers、模式枚举(`M_logo/M_menu/M_credits/M_game`)。 |
| L80–89 | 图形初始化 | `init_graphics()`:加载三张 PNG、从精灵表 (y=96, x=112..119) 取样 8 个能力色。 |
| L91–232 | 类型 / 静态数据 | 瓦片与物体枚举、精灵表索引表、`obj` 位域、`player_state`、关卡 ASCII 图例注释。 |
| L233–297 | 世界数据 | `rawmap[24][2]` 两层世界 ASCII 关卡、颜色枚举、`lightdata`(字母→色+方向)、全局玩家坐标。 |
| L299–391 | 关卡解析 | `init_game()`:ASCII → `tilemap/objmap`,放置蛋区、按相邻箭头初始化 rover 方向。 |
| L393–611 | 撤销 / 快照结构 | `roomsave_big`、`gamestate`、撤销设计注释、save/restore 一族、房间/供电/光照计算。 |
| L611–741 | 房间状态与能力 | 进入新房间存档、undo 恢复、能力表、`push_rovers`(空壳)。 |
| L742–1077 | 玩家动作 | `move/drop/reflector/shoot/do_key`:移动、开门穿墙、宝石拾取、光束操作、按键分发。 |
| L1079–1236 | Rover AI / 旋转 | `rove_allowed / preferred_rove_direction / move_rovers` 与房间旋转小工具。 |
| L1237–1383 | 时间步进 / 菜单数据 | `timestep()` 事件节拍、`restart_game()`、菜单项与 credits 数据。 |
| L1385–1566 | 元游戏(菜单/存档) | 选择逻辑、`get_savegame_path/load_game/save_game`、`do_metagame_key/process_metagame`。 |
| L1570–1721 | 绘制原语 | `draw_init/draw_rect/draw_sprite/draw_text` 等 + 内置 42 字符字体表。 |
| L1725–2418 | 场景渲染 | `draw_metagame`(Logo/菜单/Staff)与 `draw_world`(房间+光束+玩家+HUD+结尾动画)。 |
| L2420–2543 | 主循环与平台 | `draw/loopmode/winproc/stbwingraph_main`:事件 → 排队按键 → 逻辑 → 渲染。 |

## 一处阅读提示

`init_game()`(L299)的解析逻辑里 `data[x + x/SIZE_X]`(L308)专门用来**跳过每 6 字符房间之间的空格**——原始 ASCII 关卡 `rawmap`(L233)每行 24 字符,但书写时用空格把 4 个房间分隔开方便肉眼阅读,解析时代码负责跳过它们。
