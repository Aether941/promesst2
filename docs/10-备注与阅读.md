# 10. 源码“遗产”与阅读顺序

## 哪些代码其实没生效(但很有参考价值)

| 位置 | 现象 | 解读 |
|---|---|---|
| L898–1051 | 4 个不同版本的 `shoot()` 全被 `#if 0 / #elif 0` 裁掉 | 曾尝试的玩法:推石换色、**整房间旋转**(重定向所有投影器颜色)、放置/旋转反射镜、按光束改色 —— 最后保留“重定向照到自己的投影器”。房间旋转的 `magic_phase` 逻辑与 `rotate_obj/rotate_tile`(L1253–1299)至今仍编译,只是永远不会触发。 |
| L426–461 | `roomsave` 小撤销结构整段 `#if 0` | 作者注释:更省的增量撤销需处理“出房间效应”,恢复逻辑太复杂,放弃。值得一读的工程取舍记录。 |
| L726 / L812–817 | `push_rovers()` 空壳,调用处被注释 | “玩家推 rover / rover 推玩家”未完成(`move_rovers` L1191–1198 也有被裁的推玩家分支)。 |
| L1066–1069 | g / n 作弊键 | 只在 `_DEBUG || CHEAT` 下编译。 |
| L2255–2264 | HUD 的 C 键(反射镜)提示被 `#if 0` | 按键绑定仍在 `do_key`(L1065),只是不再提示。 |
| L26 | `#include <sys/state.h>`(非 Win 分支) | Linux 移植需 `mkdir/S_IRWXU`(L1450),此处疑似 `<sys/stat.h>` 笔误;目录内未提供该头文件。 |
| L1494–1496 | `save_game()` 里 `#ifndef RELEASE return;` | 非发布版故意不写盘(开发期防污染存档)。 |
| L2415–2416 | 通关后 `exit(0)` | 注释 “shouldn't call save!”—— 通关即走不落档。 |
| L1219 附近 | `obj` 是 8bit 位域;`tilemap/objmap` 各 2×24×24 = 1152 B | 全图数据紧凑,配合只存“十字带”的撤销,让“整图 + checkpoint + 撤销链”能整体进一个存档文件。 |

## 建议阅读顺序

1. **入口**:`stbwingraph_main`(L2523)→ 开局、读档、进主循环;
2. **关卡数据**:`rawmap`(L233)+ 图例注释(L226),拿 ASCII 关卡对着 `init_game`(L299)读解析;
3. **核心规则**:`move()`(L742)+ `do_key()`(L1056),理解一格移动里的所有能力判定;
4. **光束灵魂**:`propagate_light()`(L496)→ `get_abilities()`(L714)→ `shoot()`(L1026),整个谜题引擎;
5. **撤销魔法**:`save_state / restore_undo`(L613 / L641)+ L404 注释,最巧的一段;
6. **动起来**:`timestep()`(L1237)+ rover 三函数(L1093–1218);
7. **看得见**:`draw_world()`(L1851),按“地形→物体→玩家→辉光→HUD”过一遍;
8. 收尾:`save/load_game`(L1459 / L1488)与菜单(L1510)。
